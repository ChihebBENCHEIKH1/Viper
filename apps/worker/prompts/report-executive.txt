## Hallucination Cleanup Rules (MANDATORY)

Before writing ANY section, apply these filters to all source material:

1. **KEEP** sections labeled "Successfully Exploited" that contain:
   - Concrete Frida output, ADB command output, or mitmproxy captures
   - Level 3 or Level 4 evidence classification
   - Specific data samples (even if redacted)
   - Copy-paste reproduction steps

2. **REMOVE / DO NOT INCLUDE** any of the following:
   - Standalone "Potential Vulnerabilities" sections without exploitation evidence —
     these go into a separate appendix, NOT the main findings
   - Generic "Recommendations" or "Best Practices" sections not tied to a specific finding
   - "Conclusions" or "Next Steps" sections with boilerplate advice
   - Any finding that says "may be vulnerable", "could potentially", "we recommend testing"
     without corresponding exploitation evidence
   - Theoretical attack scenarios not validated by the exploitation agents

3. **PRESERVE exactly:**
   - Vulnerability IDs (MOB-VULN-XX format) — do not renumber or skip
   - Frida script snippets used in reproduction steps
   - ADB commands from reproduction steps
   - Evidence level classifications (EXPLOITED, POTENTIAL)

4. **DOWNGRADE** findings that appear in analysis deliverables but NOT in exploitation
   evidence as "Successfully Exploited" — these become "Potential" in the appendix,
   regardless of how confident the analysis agent sounded.

## Evidence Synthesis Protocol

For each finding, cross-reference the analysis deliverable with the exploitation evidence:

| Analysis Says | Exploitation Says | Report Classification |
|--------------|-------------------|----------------------|
| Vulnerable | EXPLOITED (Level 3+) | Main Finding — CONFIRMED |
| Vulnerable | POTENTIAL (Level 1-2) | Appendix — Potential (Unverified) |
| Vulnerable | FALSE POSITIVE | Omit from report entirely |
| Vulnerable | Not attempted | Appendix — Potential (Not Tested) |

**Rule:** A finding MUST have Level 3+ exploitation evidence to appear in the main
"Detailed Findings" section. Everything else goes to the appendix.

## CVSS Scoring Guidance

Score each finding using CVSS v3.1 with these mobile-specific adjustments:

**Attack Vector (AV):**
- Network (N): Exploitable via network traffic (MITM, API tampering)
- Local (L): Requires physical device access or malicious app on same device
- Physical (P): Requires USB/ADB access to the device

**Reflect ACTUAL exploitability, not theoretical maximum:**
- If exploitation required root + Frida + specific app version, score complexity as High
- If exploitation worked via simple ADB command, score complexity as Low
- If exploitation required user interaction (clicking a link), mark UI as Required

**Common Mobile Vulnerability CVSS Profiles:**
| Vulnerability Type | Typical Vector | Typical Score Range |
|-------------------|---------------|-------------------|
| Exported ContentProvider SQLi | AV:L/AC:L/PR:N/UI:N | 7.0-8.5 |
| Plaintext credential storage (debuggable) | AV:L/AC:L/PR:N/UI:N | 5.5-7.0 |
| Plaintext credential storage (backup) | AV:P/AC:L/PR:N/UI:R | 4.0-5.5 |
| SSL pinning bypass + sensitive data | AV:N/AC:H/PR:N/UI:N | 5.9-7.5 |
| Biometric bypass to protected data | AV:L/AC:L/PR:N/UI:N | 6.5-8.0 |
| Weak crypto with key extraction | AV:L/AC:L/PR:N/UI:N | 6.0-7.5 |
| Root detection bypass (enabler) | AV:L/AC:L/PR:N/UI:N | 3.0-5.0 |
| WebView JS injection | AV:N/AC:L/PR:N/UI:R | 6.0-8.0 |

## Report Structure

Save to: `{{DECOMPILED_PATH}}/../deliverables/executive_report.md`

### 1. Executive Summary
- Application: name, version, package name
- Assessment date and duration
- Testing scope: black-box / white-box, tools used
- Overall risk rating: CRITICAL / HIGH / MEDIUM / LOW (based on highest exploited finding)
- Key metrics: X findings exploited, Y potential, Z categories tested
- Top 3 most critical exploited findings (one sentence each with business impact)

### 2. Methodology
- Approach: Static analysis (JADX, APKTool) + Dynamic testing (Frida, Appium) +
  Exploitation verification
- Coverage: OWASP Mobile Top 10 2024, 5 parallel analysis domains
  (storage, crypto, auth, network, injection)
- Evidence standard: 4-level proof system — only Level 3+ classified as Exploited
- Tools and versions used

### 3. Findings Summary Table
| ID | Finding | OWASP | Severity | CVSS | MASTG | Status |
|----|---------|-------|----------|------|-------|--------|
| MOB-VULN-01 | ... | M9 | CRITICAL | 8.5 | MASTG-TEST-0001 | Exploited |

### 4. Detailed Findings
For EACH finding with Level 3+ exploitation evidence:

- **ID:** MOB-VULN-XX
- **Title:** Descriptive vulnerability title (noun phrase, not a sentence)
- **Severity:** CRITICAL / HIGH / MEDIUM / LOW
- **CVSS Score:** X.X (CVSS:3.1/AV:../AC:../PR:../UI:../S:../C:../I:../A:..)
- **OWASP Category:** M1-M10 with category name
- **MASTG Test ID:** MASTG-TEST-XXXX
- **Description:** What the vulnerability is and why it matters, in 2-3 sentences.
  Reference the specific code location or component.
- **Evidence:** Direct quotes from exploitation evidence — Frida output, extracted data,
  ADB output. Include the evidence level (Level 3 or 4).
- **Impact:** What an attacker gains in BUSINESS terms. Quantify where possible:
  "All user credentials stored on the device" not "data can be extracted."
- **Reproduction Steps:** Numbered, copy-paste ready commands. Include Frida scripts
  inline. Another analyst must reproduce this without additional context.
- **Remediation:** Specific code-level fix with example. Not "use encryption" but
  "Replace SharedPreferences with EncryptedSharedPreferences using MasterKey.Builder
  with AES256_GCM scheme."

### 5. Risk Matrix
| Category | Critical | High | Medium | Low | Total |
|----------|----------|------|--------|-----|-------|
| Data Storage (M9) | | | | | |
| Cryptography (M10) | | | | | |
| Authentication (M3) | | | | | |
| Network (M5) | | | | | |
| Injection (M4) | | | | | |
| **Total** | | | | | |

### 6. Remediation Priority
Ordered list by risk-to-effort ratio (highest impact, lowest effort first):
| Priority | Finding ID | Fix | Effort | Risk Reduction |
|----------|-----------|-----|--------|---------------|
| 1 | MOB-VULN-XX | ... | Low/Med/High | Critical/High/Med |

### 7. Appendix

#### A. Potential Vulnerabilities (Unverified)
Findings with Level 1-2 evidence only. Brief description + why exploitation was blocked.

#### B. Compliance Mapping
Full OWASP Mobile Top 10 2024 coverage matrix.
PCI-DSS / HIPAA / NIST mapping where applicable.

#### C. Tool Versions
| Tool | Version | Purpose |
|------|---------|---------|
| JADX | ... | Decompilation |
| APKTool | ... | Resource extraction |
| Frida | ... | Runtime instrumentation |
| Appium | ... | UI automation |
| mitmproxy | ... | Traffic interception |

#### D. Testing Timeline
Phase-by-phase timeline with duration per phase.

#### E. Scope Limitations
Document any areas not tested and why (e.g., server-side not in scope,
hardware security module not available on emulator).
